# HU-20 · Manifest e instalación — evidencias

Build local: `npx expo export -p web` y `dist/` servido en `http://localhost:8095` (localhost cuenta como contexto seguro).
Revisión con Chrome DevTools Protocol (`Page.getAppManifest` y `Page.getInstallabilityErrors`), que son los mismos datos de DevTools → Application → Manifest.

| Criterio | Evidencia | Resultado |
|---|---|---|
| 1. El navegador ofrece instalar | `hu20_manifest_instalabilidad.txt`: "Errores de instalabilidad: ninguno" | OK |
| 2. Abre en modo standalone | El manifest se interpreta con `display: kStandalone`, `start_url` y `scope` en `/` | OK (la prueba en un teléfono real queda para revisión manual) |
| 3. El ícono coincide con el manifest | `/icons/*.png` responden 200 `image/png`; ver `hu20_icono_512.png` y `hu20_icono_maskable_512.png` | OK |
| 4. Sin errores de instalabilidad | "Errores de parseo del manifest: ninguno" · "Errores de JavaScript: ninguno" | OK |

Archivos:
- `public/manifest.json`: nombre, colores, idioma e íconos (192, 512 y 512 maskable).
- `public/index.html`: plantilla que Expo usa al exportar. Incluye el link al manifest, apple-touch-icon 180, `viewport-fit=cover`, metas de Apple y padding de áreas seguras en `#root`.
- `assets/pwa/*.svg`: fuente de los íconos (estrella crema en círculo vino con anillo dorado, sobre #2b1f24).

`orientation` no se fijó a propósito: la app se usa también en horizontal (tablet y escritorio).
